# Автоматический подбор музыки для коротких видео

Учебный проект по Computer Vision / Multimodal ML. Цель проекта: по короткому видео вернуть топ музыкальных дорожек, которые лучше всего подходят к визуальному контенту.

Проект сделан как реалистичный baseline, который можно запустить в Google Colab. Вместо тяжёлого fine-tuning больших мультимодальных моделей здесь используется простой retrieval-пайплайн:

1. Берём небольшую подвыборку HarmonySet.
2. Скачиваем доступные YouTube-видео.
3. Из каждого видео извлекаем визуальные признаки по нескольким кадрам.
4. Из аудиодорожки извлекаем простые mel-признаки.
5. Обучаем two-tower модель: одна башня для видео, другая для музыки.
6. Оцениваем ранжирование через Hit@1, Hit@5 и MRR.

Такой вариант проще, чем VideoLLaMA2/CLAP fine-tuning, но он честно реализует полный ML-пайплайн: данные, признаки, обучение, валидация, метрики, анализ ошибок и демо.

## Почему Colab подходит

Google Colab подходит для этого проекта: там есть GPU, ffmpeg, достаточно памяти для небольшой подвыборки, а преподаватель сможет открыть ноутбук и повторить основные шаги. Ограничение: скачивание видео с YouTube может быть нестабильным, поэтому проект фильтрует битые ссылки и работает с тем, что реально скачалось.

## Установка

Локально:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

В Colab проще запустить первую ячейку ноутбука `notebooks/colab_train_music_retrieval.ipynb`.

## Быстрый запуск

Для быстрой проверки можно скачать маленькую подвыборку:

```bash
python -m src.data.download_harmonyset --limit 30
python -m src.data.build_manifest
python -m src.features.extract_features
python -m src.train
python -m src.evaluate --split test
```

Для финального эксперимента в Colab лучше начать с `--limit 100`, а потом увеличить до `300-1000`, если время позволяет.

## Демо-инференс

После обучения:

```bash
python -m src.infer --video-id 0 --top-k 5
```

Скрипт берёт видео из manifest/test split и показывает топ-5 аудио из базы по близости эмбеддингов.

## Метрики

В проекте используются:

- `Hit@1`: правильная музыка оказалась на первом месте.
- `Hit@5`: правильная музыка попала в топ-5.
- `MRR`: учитывает позицию правильного трека в ранжировании.

Для сравнения дополнительно считается random baseline. Это важно: даже если абсолютные числа не очень высокие, можно показать, что обученная модель лучше случайного выбора.

## Ограничения

- Положительная пара строится из исходного видео и его аудиодорожки. Это не идеально, но соответствует доступной структуре HarmonySet и задаче retrieval.
- Модель видит усреднённые признаки, поэтому плохо учитывает точную синхронизацию по времени.
- YouTube-ссылки могут быть недоступны, поэтому размер датасета после скачивания обычно меньше запрошенного.
- Это baseline, а не попытка повторить результаты статьи HarmonySet.

1. Постановку задачи: подбор топ-K музыки для видео.

3. Пайплайн: скачивание, фильтрация, признаки, two-tower модель.
4. Метрики Hit@1, Hit@5, MRR и сравнение с random baseline.
