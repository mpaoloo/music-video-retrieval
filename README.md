# Music Video Retrieval

Проект по Computer Vision / мультимодальному ML: по короткому видео нужно подобрать подходящую музыкальную дорожку из базы кандидатов.

## Идея

Для каждого видео модель строит эмбеддинг, для каждой аудиодорожки строит эмбеддинг в том же пространстве, а затем ранжирует музыку по косинусной близости.

Данные берутся из `Zzitang/HarmonySet`: датасет содержит пары видео и музыки, а также текстовые аннотации. Сами видео скачиваются по YouTube-ссылкам, поэтому пайплайн дополнительно фильтрует недоступные и повреждённые файлы.

## Пайплайн

1. `src.data.download_harmonyset` скачивает метаданные HarmonySet и доступные видео.
2. `src.data.build_manifest` проверяет видео через OpenCV, считает длительность/FPS/кадры и делает train/val/test split.
3. `src.features.extract_features` извлекает признаки:
   - видео: несколько равномерно выбранных кадров, ResNet50 без классификатора, усреднение по кадрам;
   - аудио: mono wav через ffmpeg, log-mel спектрограмма, mean/std по mel-полосам.
4. `src.train` обучает two-tower модель с contrastive loss.
5. `src.evaluate` считает Hit@1, Hit@5, MRR и random baseline.
6. `src.infer` показывает top-k рекомендаций для выбранного видео.

## Текущая конфигурация

Основные параметры лежат в `configs/config.yaml`:

- `frame_count: 16`
- `n_mels: 96`
- `embedding_dim: 256`
- `batch_size: 48`
- `epochs: 30`
- `learning_rate: 0.0005`
- для извлечения видео фичей используется модель ResNet50 с удаленным последним классификационным слоем

## Запуск

Локально:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Основные шаги:

```bash
python -m src.data.download_harmonyset --limit 500
python -m src.data.build_manifest
python -m src.features.extract_features
python -m src.train
python -m src.evaluate --split test
python -m src.infer --split test --row-index 0 --top-k 5
```

В Colab тот же пайплайн можно запускать через `notebooks/colab_train_music_retrieval.ipynb`.

## Результаты

В эксперименте на подвыборке около 500 исходных примеров после фильтрации получилось 418 строк с извлечёнными признаками. На test split из 63 кандидатов модель показала:

- `Hit@1 = 0.0159`
- `Hit@5 = 0.1429`
- `MRR = 0.0905`

Random baseline для того же test split:

- `Hit@1 = 0.0159`
- `Hit@5 = 0.0794`
- `MRR = 0.0751`

Модель заметно улучшает `Hit@5` и немного улучшает `MRR`, но абсолютное качество пока невысокое. Это ожидаемо для небольшого датасета, простых аудиопризаков и усреднения кадров по времени

## Ограничения

- Часть YouTube-ссылок недоступна или скачивается с ошибками.
- Видео представляется средним вектором по кадрам, без явного моделирования динамики.
- Аудио описывается простыми log-mel статистиками
- Пары строятся из исходного видео и его аудиодорожки. задача не оценивает субъективную музыкальную совместимость вручную.

## Что можно улучшить

- Увеличить размер выборки
- Использовать CLIP/CLAP или другой мультимодальный вариант.
- Добавить временную модель поверх кадров/аудио.
